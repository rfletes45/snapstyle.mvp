## 12. Reaction System

### UX Flow

1. **Long-press a message** -> `MessageActionsSheet` opens
2. **Quick reactions** - 6 curated emojis (`👍 ❤️ 😂 😮 😢 🔥`) at top of sheet
3. **"+" button** - opens the full emoji picker (`rn-emoji-keyboard`) with categories, search, recent, and skin tones
4. **Selecting an emoji** closes the picker/sheet and calls `toggleReactionV2` on the server
5. **Reaction pills** appear below the message bubble (emoji + count). Tapping toggles participation
6. **Tapping your own pill** removes the reaction

### Data Model

**Message document** (`reactionsSummary`):

```text
Chats/{chatId}/Messages/{messageId}
Groups/{groupId}/Messages/{messageId}
  reactionsSummary: Record<string, number>  // { "🔥": 2, "❤️": 1 }
```

**Reactions subcollection**:

```text
.../Messages/{messageId}/Reactions/{emoji}
  emoji: string
  uids: string[]
  count: number
  updatedAt: number
```

- document ID = emoji character
- max 20 unique emojis per message
- max 10 users displayed per emoji in the detail sheet

### Service Layer

| Function | Description |
| -------- | ----------- |
| `toggleReaction()` | Calls `toggleReactionV2` Cloud Function |
| `applyOptimisticReaction()` | Pure function: computes next reactions array locally |
| `subscribeToReactions()` | Real-time Firestore listener for one message |
| `subscribeToMultipleMessageReactions()` | Batch subscription for visible messages |
| `getReactions()` | One-shot fetch |
| `parseReactionsFromMessage()` | Parse denormalized summary into `ReactionSummary[]` |

All live in `src/services/reactions.ts`.

### Cloud Function (`toggleReactionV2`)

- **Input**: `{ conversationId, scope, messageId, emoji }`
- **Validation**: auth, membership, rate limit (`10/min`), emoji length <= `10` chars
- **Logic**: Firestore transaction that adds/removes the UID and updates denormalized `reactionsSummary`
- **Output**: `{ success, action: "added"|"removed", reactionsSummary }`

### Optimistic Updates

1. User taps a reaction -> `applyOptimisticReaction()` computes the next local state
2. Parent screen calls `setMessageReactions()` immediately with the optimistic result
3. Cloud Function call is fired in the background
4. On success, the Firestore listener overwrites with authoritative state
5. On failure, `applyOptimisticReaction()` is called again to roll back

**Key details:**

- per-emoji debounce uses an `inflight` ref to prevent double-taps on the same emoji
- an `optimisticIds` ref keeps optimistic messages inside the subscription set, fixing the first-reaction blind spot
- the old single `loadingEmoji` state is gone

### Subscription Stability

Both chat screens use a `reactionTargetKey`, a memoized sorted comma-joined string of visible message IDs, as the `useEffect` dependency. The subscription only rebuilds when the set of message IDs actually changes.

### Animations

- **Pill tap**: spring scale (`withSequence(withSpring(1.25), withSpring(1))`)
- **Pill enter/exit**: `FadeIn.duration(200)` / `FadeOut.duration(150)`
- **Layout transitions**: `LinearTransition.springify()`
- **Haptic feedback**: `expo-haptics` `ImpactFeedbackStyle.Light`
- **Theme-aware**: `primaryContainer`/`primary` for your own reactions, `surfaceVariant` for others

### Preview and Long-Press Representation

The reactions detail surface and the long-press surface now have distinct responsibilities:

- `ReactionDetailSheet.tsx` is a reactor list only. It shows emoji tabs plus users; it does not render a message-text preview.
- `MessageActionsSheet.tsx` is where long-press preview text, copy text, and reply metadata are derived.
- `SwipeableMessage.tsx` mirrors the same reply-snippet sanitization rules when swipe-to-reply is used instead of long-press.
- scorecards are normalized to `Game Scorecard` in those surfaces so the raw sentinel plus embedded JSON never leaks into reply snippets, copy actions, or long-press previews

### Known Limitations

- denormalized `reactionsSummary` does not include per-user data, so `hasReacted` is always `false` from summary alone; full reaction subscriptions are still needed for accurate state
- `ReactionDetailSheet` batch-fetches all reactor profiles on open using `batchFetchProfiles()` (Firestore `documentId() in [...]` query, max `30` per chunk)
- if the Cloud Function fails silently, optimistic state persists until the Firestore listener delivers authoritative data
