## 15. Message Features

### Scorecards

Scorecards are a chat surface, not a new message kind.

Render path:

- transport is a `kind: "text"` message whose `text` field carries the scorecard sentinel plus JSON payload
- `getTrustedScorecardPayload()` only trusts messages whose `clientId` is `"server"` or starts with `"server-share:"`
- DM and group screens decode scorecards before the normal system-message fallback and mount `ChatScorecardMessage`
- `ChatScorecardMessage` participates in sender chrome, reactions, threads, swipe-to-reply, long-press, accessibility labeling, and stacked grouped-card behavior
- in stacked group mode the wrapper mirrors grouped-card surface rules so the fixed-width `<GameScorecard />` slots into grouped runs cleanly

Preview and plaintext behavior:

- inbox conversation rows and aggregated inbox triggers substitute `Game Scorecard`
- long-press preview text, clipboard copy, and reply snippets also substitute `Game Scorecard`
- replying to a scorecard is supported; the reply preview points at the scorecard message, but text fallback remains generic
- `ReactionDetailSheet` does not show message preview text at all; it only lists reactors
- accessibility labels use sender display name plus game title, not the raw wire text

Privacy and trust hardening:

- raw sentinel text alone is not trusted and is intentionally rejected by `sendMessageV2`
- rich render requires a trusted `clientId` that survives Firestore sync and SQLite hydration through the `client_id` migration
- manual scorecard sharing uses structured `scorecardPayload`, which the server validates and re-encodes
- current exception: legacy push preview code in `firebase-backend/functions/src/notifications.ts` still reads raw `message.text`; see [Section 23](#23-known-issues--risks)

### Voice Messages

- compose-time UI ownership lives in `ChatComposer.tsx`, `VoiceRecordButton.tsx`, `VoiceRecordingHost.tsx`, and `useVoiceRecorder.ts`
- send flow uses `sendVoiceRecordingMessage()` in `src/chat/sendDraft.ts`, which sends `kind: "voice"` with audio attachment metadata
- playback remains owned by `VoiceMessagePlayer.tsx`

### Mentions (Group Only)

- stored on message as `mentionUids` and `mentionSpans`
- compose-time suggestions come from `MentionAutocomplete.tsx`
- group stacked rendering uses `MessageWithMentions`

### Attachments

Two-phase flow:

1. Client uploads to `chat-staging/...`
2. `sendMessageV2` finalizes into `chat-media/...`

Constraints are enforced server-side in `chatMedia.ts`. DM and group screens share attachment send orchestration for tray attachments, direct camera sends, and direct gallery sends.

### Scheduled Messages

- client service: `src/services/scheduledMessages.ts`
- management screen: `ScheduledMessagesScreen.tsx`
- backend processing remains a legacy-style proxy but is still active

### Message Requests

Always on - no client-side feature flag.

- backend enforcement: `messageRequests.ts`
- client subscription: `useMessageRequests.ts`
- merge surface: `useUnifiedInboxRequests.ts`
