# Data Sources and Persistence

Last verified: 2026-03-27

← Back to [Profile System Overview](PROFILE_SYSTEM_OVERVIEW.md)

This document covers where widget data comes from, how widget layouts are stored, and the source-of-truth rules for the profile system.

## Widget Layout Persistence

### Firestore Path

```
Users/{userId}/ProfileLayout/board
```

This single document stores the complete widget board state.

### Schema

```typescript
{
  schemaVersion: 1,            // Current LAYOUT_SCHEMA_VERSION
  widgets: WidgetInstance[],   // All widgets (visible + hidden)
  updatedAt: string            // ISO 8601 timestamp of last save
}
```

### Widget Instance Shape

```typescript
interface WidgetInstance {
  instanceId: string; // UUID, unique per instance
  widgetType: WidgetTypeId; // e.g. "profile-header", "friends"
  size: WidgetSizeKey; // "small" | "medium" | "wide" | "large" | "hero"
  x: number; // Grid column (0-based, 0 to 3)
  y: number; // Grid row (0-based, unbounded)
  visible: boolean; // On board (true) or hidden (false)
  pinned: boolean; // Currently only profile-header uses this
  config: Record<string, unknown>; // Widget-type-specific config
  createdAt: string; // ISO 8601 timestamp
  updatedAt: string; // ISO 8601 timestamp
}
```

### Load/Save Flow

**File:** `src/components/profile/WidgetBoard/useBoardPersistence.ts`

**Initial load:**

1. Fetch `Users/{userId}/ProfileLayout/board` via `getDoc()`
2. If document exists → `validateAndMigrate()` checks schema version and widget integrity
3. If document missing or invalid → `generateDefaultLayout()` creates default board
4. Default layout is persisted back to Firestore (best-effort)
5. Hook sets `loaded: true`

**Real-time sync:**

- `onSnapshot()` listener watches for external changes (e.g., editing from another device)
- **Echo guard:** After a save, the listener ignores changes for 500ms to avoid reacting to its own write (via `savingRef.current` flag)

**Save:**

1. Update local state immediately (optimistic)
2. Write full layout document to Firestore via `setDoc()`
3. If Firestore is unreachable, succeed locally only (graceful degradation)
4. Echo-guard timeout starts, preventing listener from re-applying the just-saved data

### Validation and Migration

On load, the persistence layer:

- Checks `schemaVersion` — warns if newer than expected, falls back to defaults
- Filters out unknown widget types (with warning logs)
- Validates `instanceId`, `size`, and grid coordinates per widget
- **Ensures profile-header exists** — inserts it at (0, 0) hero size if missing
- Returns `null` if data is unrecoverably corrupt (triggers default layout generation)

### Default Layout

Generated by `generateDefaultLayout()` in `BoardLayoutEngine.ts`:

| Widget         | Size         | Position (x, y) |
| -------------- | ------------ | --------------- |
| profile-header | hero (4×4)   | (0, 0)          |
| social-proof   | wide (4×1)   | (0, 4)          |
| friends        | medium (2×2) | (0, 5)          |
| badges         | medium (2×2) | (2, 5)          |
| achievements   | wide (4×1)   | (0, 7)          |

Widgets not in the default layout (favorite-game, profile-stats, recent-activity, mutual-friends) can be added by the user via the Widget Gallery.

## Widget Data Sources

Each widget type receives its data through the `widgetData` memo in `OwnProfileScreen.tsx`. Data is prepared from multiple hooks and passed to `WidgetBoardContainer`.

### Canonical Data Sources Per Widget

| Widget              | Data Source(s)                            | Hook(s)                                                                          | Firestore Path(s)                                              |
| ------------------- | ----------------------------------------- | -------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| **profile-header**  | Profile data, picture, level, rewards     | `useProfileData`, `useFullProfileData`, `useProfilePicture`, `usePendingRewards` | `Users/{uid}`                                                  |
| **social-proof**    | Friend streaks (real-time)                | `useTopStreaks`                                                                  | `Friends` collection (filtered by uid)                         |
| **friends**         | Friends list (fetched internally by card) | Internal to `FriendsCard`                                                        | `Users/{uid}/Friends` or `Friends`                             |
| **badges**          | Featured badges                           | `useProfileData`                                                                 | `Users/{uid}.featuredBadges`                                   |
| **achievements**    | Featured achievement IDs                  | `useFullProfileData`                                                             | `Users/{uid}.featuredAchievements`, `Users/{uid}/Achievements` |
| **favorite-game**   | Personal best records                     | `useGameStatsV4`                                                                 | `Users/{uid}/GamePB/{gameId}`                                  |
| **profile-stats**   | Global game stats + friend count          | `useGameStatsV4`, `useProfileData`                                               | `Users/{uid}`, game PB subcollection                           |
| **recent-activity** | Activity events                           | `fetchUserActivities()` side effect                                              | `Users/{uid}/activity`                                         |
| **mutual-friends**  | (Not populated on own profile)            | `getMutualFriends()`                                                             | `Friends` collection                                           |

### Source-of-Truth Rules

These are the canonical sources of truth for profile-related data. If data disagrees between caches and Firestore, **Firestore wins**.

| Data                                 | Canonical Source                                  | Notes                                                          |
| ------------------------------------ | ------------------------------------------------- | -------------------------------------------------------------- |
| Profile identity (name, bio, status) | `Users/{uid}` document                            | Written by `profileService.ts`                                 |
| Profile picture                      | `Users/{uid}.profilePicture.url`                  | Updated via picture upload flow                                |
| Avatar decoration                    | `Users/{uid}.avatarDecoration.decorationId`       | Written via Customization Hub equip                            |
| Background                           | `Users/{uid}.equippedBackgroundId`                | Written via Customization Hub equip                            |
| Level/XP                             | `Users/{uid}` (computed by server)                | Server-authoritative; client uses `useProfileData` cached view |
| Featured badges                      | `Users/{uid}.featuredBadges.badgeIds`             | Written via Customization Hub                                  |
| Featured achievements                | `Users/{uid}.featuredAchievements.achievementIds` | Written via trophy case UI                                     |
| Streak data                          | `Friends/{friendshipId}` document                 | Server-authoritative; `useTopStreaks` subscribes real-time     |
| Game stats                           | `Users/{uid}/GamePB/{gameId}`                     | Written by game resolution pipeline (server)                   |
| Widget layout                        | `Users/{userId}/ProfileLayout/board`              | Written by board persistence hook                              |
| Cosmetic entitlements                | `Users/{uid}/Entitlements/{cosmeticId}`           | Written by Cloud Functions (purchase/grant)                    |
| Privacy settings                     | `Users/{uid}.privacy`                             | Written by privacy settings UI                                 |
| Activity events                      | `Users/{uid}/activity` subcollection              | Written by server triggers on various events                   |

## Profile Data Hooks

### useProfileData(uid)

Returns basic profile data including level, stats, and featured badges. Uses stale-while-revalidate caching via `profileCache` service with cache keys `"stats"` and `"level"` per UID.

### useFullProfileData({userId})

Returns extended profile data: bio, status, privacy settings, featured achievements. Fetched on mount and on refresh.

### useProfilePicture(uid)

Returns `pictureUrl: string | null` and `decorationId: string | null`. Refreshable.

### useTopStreaks(uid)

**File:** `src/hooks/useTopStreaks.ts`

Real-time Firestore subscription to the `Friends` collection where the user is a participant. Returns:

```typescript
interface TopStreaksResult {
  streaks: StreakSummary[]; // Top 5 streaks, enriched with partner profiles
  activeStreakCount: number; // Total active streaks
  topStreakCount: number; // Highest streak count
  loading: boolean;
  error: string | null;
}

interface StreakSummary {
  friendshipId: string;
  partnerUid: string;
  partnerName: string;
  partnerPictureUrl: string | null;
  partnerDecorationId: string | null;
  streakCount: number;
  bestStreak: number;
  status: "active" | "at_risk" | "expired" | "none";
  nextMilestone: number;
  graceUsed: boolean;
}
```

Status is derived via `deriveStreakStatus()` from `src/services/streakCosmetics.ts`. Next milestone is computed via `nextMilestone()` from the same file.

Partner profile data (name, picture, decoration) is enriched via one-time `getUserProfileByUid()` calls — **not** real-time subscriptions. Avatar changes require hook remount or page refresh to update.

### useGameStatsV4()

Returns global game stats (`gamesPlayed`, `gamesWon`) and personal bests array. Used by **favorite-game** and **profile-stats** widgets.

### usePendingRewards()

Returns `{ unclaimedLevelRewardCount: number }` — shown in the hero card's level section.

## Privacy Model Integration

Widget data respects privacy settings at the `OwnProfileScreen` level:

```typescript
const friendsHidden = privacy?.showFriendsList === "nobody";
const badgesHidden = privacy?.showBadges === "nobody";
const achievementsHidden = privacy?.showAchievements === "nobody";
const streaksHidden = privacy?.showStreaks === "nobody";
const activityHidden = privacy?.showRecentActivity === "nobody";
```

When hidden, widgets show a "Hidden from others" indicator on the own profile. On other users' profiles (`UserProfileScreen`), hidden data is evaluated against the viewer's relationship:

- `"nobody"` → always hidden
- `"friends"` + not friends → hidden
- `"everyone"` → visible

## Favorite Game Derivation

Favorite game is **computed, not user-selected**:

1. `useGameStatsV4()` returns personal best records (`pbs[]`)
2. Sort by `totalPlays` descending
3. Take `pbs[0]` (most-played game)
4. Format game name: convert `gameId` ("tic-tac-toe" → "Tic Tac Toe")
5. Compute win rate: `(totalWins / totalPlays) × 100`

> Note: `configurable: true` is set in the widget registry, suggesting future support for user-selected favorite game. Currently, it is always auto-derived.

## Recent Activity Collection

**Firestore path:** `Users/{uid}/activity`

Activities are written by server-side triggers when events occur. The client fetches the 5 most recent via `fetchUserActivities(uid, 5)` as a side effect in `OwnProfileScreen`.

Each activity document contains:

- `type` — event type string
- `text` — human-readable description
- `createdAt` — timestamp

The screen reformats activities with time-ago strings and Material Community Icons before passing to the widget.

## Mutual Friends Computation

**Service:** `getMutualFriends(currentUserId, targetUserId)` in `profileService`

1. Fetches both users' friend lists
2. Computes set intersection on UIDs
3. Fetches full profiles for mutual UIDs (limit 10)
4. Returns `MutualFriendInfo[]`

On own profile: Currently hardcoded to pass empty array (mutual friends are semantically meaningless for self).
