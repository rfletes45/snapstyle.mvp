# Full System Sweep Audit

## Purpose

This document is the source of truth for the SnapStyle full-system cleanup sweep. Every stale, debug, deprecated, redundant, duplicate, unused, temporary, or otherwise questionable cleanup candidate must be recorded here before implementation work removes or refactors it.

The sweep is split into two laps:

1. Lap 1 documents candidates with evidence and reference checks.
2. Lap 2 implements safe cleanup batches from this document, updating status and validation as work proceeds.

## Sweep Rules

- Delete only after the item is documented, classified, and reference-checked.
- Keep code that is actively used, security-sensitive, migration-sensitive, deploy-sensitive, or required for backward compatibility.
- Refactor or consolidate only when a canonical replacement is clear and references can be migrated safely.
- Gate development-only diagnostics behind existing debug/dev controls when diagnostics remain useful.
- Defer uncertain removals when dynamic references, production data compatibility, Firebase deployment state, or asset manifests make deletion unsafe.
- Do not remove Cloud Functions exports, Firebase rules/indexes, local migrations, or compatibility paths without production-impact evidence.
- Treat console logging case-by-case: remove stale debug noise, keep meaningful error reporting, and avoid logging sensitive data.
- Preserve unrelated user changes. Initial baseline: clean worktree.
